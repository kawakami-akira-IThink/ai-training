# 仕様書：顧客マスタ API（CRUD）

## 目的
顧客情報の登録・変更・検索・削除ができる API を提供する。

## 対象ユーザー
営業

## データ項目

| 項目 | 型 | 必須 | ルール |
|------|----|------|--------|
| id | 整数 | — | 登録時にサーバーが採番する。変更・削除はこの id で対象を指定する |
| name（名前） | 文字列 | 必須 | 1〜256文字 |
| age（年齢） | 整数 | 必須 | 0〜1000 |
| gender（性別） | 文字列 | 必須 | 戸籍上の身体性別のみ：`male` / `female` |
| job（仕事） | 文字列 | 任意 | 0〜256文字 |

- 【AI補完】名前の下限は1文字（空文字は不可）、年齢の下限は0とする。
- 【AI補完】仕事は任意項目とする（未指定時は空文字）。

## 入力（API）

| 操作 | メソッド・パス | 入力 |
|------|----------------|------|
| 登録 | `POST /customers` | name, age, gender, job |
| 変更 | `PUT /customers/{id}` | name, age, gender, job |
| 削除 | `DELETE /customers/{id}` | なし |
| 検索 | `GET /customers?name=&age=&gender=&job=` | 検索条件（任意の組み合わせ） |

- 【AI補完】変更は全項目を送る置き換え方式（PUT）とする。

## 出力
- 登録・変更・削除は、正常か異常かだけを返す。
  - 【AI補完】登録の正常時のみ、採番した `id` を返す。
- 検索は、指定した条件に**すべて完全一致（AND）** する顧客を返す。
  - 条件を何も指定しない場合は 0件を返す（全件は返さない）。
  - 件数は多くない前提なので、ページングは不要。
- 異常時は HTTP ステータスとエラーコードを返す。形式：`{"code": "...", "message": "..."}`

| HTTP | code | 発生条件 |
|------|------|----------|
| 400 | `VALIDATION_ERROR` | 入力値がルール違反 |
| 401 | `UNAUTHORIZED` | 認証トークンがない、または不正 |
| 404 | `NOT_FOUND` | 指定した id の顧客が存在しない |
| 409 | `DUPLICATE` | 全項目が一致する顧客がすでに存在する |
| 409 | `LOCKED` | 対象の顧客が別の処理で変更・削除中（ロック中） |

- 【AI補完】`LOCKED` は `DUPLICATE` と区別するため、別のコードにする。

## 制約
- 言語：Python
- フレームワーク：FastAPI
- 保存先：SQLite
- 変更・削除は **DB トランザクションでロック** してから行う。ロックが取れない場合は待たずにエラー（`LOCKED`）にする。
  - 【AI補完】SQLite には行ロックがないため、`BEGIN IMMEDIATE` で書き込みロックを取り、待ち時間（busy timeout）を 0 にして即エラーにする。そのため、実際にはテーブル全体（DB全体）がロックされる。

## 受入基準

### 正常系
- 【AI補完】顧客を登録すると、全項目が一致する条件で検索したときにその顧客が見つかる。
- 【AI補完】顧客を変更すると、検索結果に変更後の内容が反映される。
- 【AI補完】顧客を削除すると、検索しても見つからない。
- 検索条件を何も指定しない場合は 0件が返る。

### 異常系
- 登録・変更で、全項目が一致する顧客がすでにいる場合はエラー（`DUPLICATE`）になる。
  - 【AI補完】変更で、自分自身と全項目が一致する（つまり何も変わらない）場合はエラーにしない。
- 変更・削除の処理中（ロック中）に、同じ対象への変更・削除が来た場合はエラー（`LOCKED`）になる。
- 【AI補完】項目のルール違反（文字数超過、年齢の範囲外、性別が male / female 以外）は `VALIDATION_ERROR` になる。
- 【AI補完】存在しない id を変更・削除しようとすると `NOT_FOUND` になる。
- 【AI補完】認証トークンがない、または不正な場合は `UNAUTHORIZED` になる。

## セキュリティ上の注意
- 本来は厳重に扱うべき個人情報だが、今回は演習なので作り込みは省略する。
- **認証**：本来は OAuth 認証を行う想定。今回は「**OAuth が実装済みである**」という仮定を置き、そのスタブとして `Authorization: Bearer <固定値>` との一致だけをチェックする。
  - これは正しい認証方式として採用するものではなく、あくまで仮置き。トークンの発行・検証は扱わない。
  - 【AI補完】固定値はコードに直接書かず、環境変数から読み込む。
- **ログ**：顧客情報をログに出す場合は、**復号可能な方式で暗号化**して出力する。
  - 【AI補完】方式は共通鍵暗号（Python `cryptography` の Fernet）とし、鍵は環境変数から読み込む。
  - 【AI補完】id、HTTP ステータス、エラーコードは暗号化せず平文で出力する（個人情報ではないため）。
- **データ**：使うのはダミーデータだけ。実在する顧客情報は使わない。
