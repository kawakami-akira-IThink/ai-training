# IF仕様書（API定義書）: 在庫管理システム

総務部が扱う日用品の品目と在庫数を管理する REST API の仕様書です。
関連文書: `doc/system_setting.md`（システム設定）、`doc/pbi.md`（PBIと受入条件）

- バックエンド: Python (FastAPI) + SQLite
- フロントエンド: React + TypeScript（Vite）から呼び出す
- 本書は Step 3（多言語文言定義書・エラー番号定義書）と Step 4（API実装・言語切り替え）を見越した設計としている

## エンドポイント一覧

| No | メソッド | URI | 概要 | 対応PBI |
|---|---|---|---|---|
| API-1 | GET | `/api/items` | 品目一覧の取得（ID昇順） | PBI-1 |
| API-2 | POST | `/api/items` | 品目の追加 | PBI-2 |
| API-3 | DELETE | `/api/items/{id}` | 品目の削除 | PBI-3 |
| API-4 | POST | `/api/items/{id}/adjust` | 在庫の増減（楽観ロック付き） | PBI-4 |

## 1. 共通事項

### 1.1 ベースURL

| 環境 | ベースURL |
|---|---|
| ローカル開発 | `http://localhost:8000/api` |

以降、URI は `/api` 以下を `/items` のように表記する箇所と、`/api/items` のように完全表記する箇所があるが、実際のリクエスト先は常に「ベースURL + パス」である。

### 1.2 CORS

フロントエンド（Vite 開発サーバ。既定 `http://localhost:5173`）とバックエンド（`http://localhost:8000`）はオリジンが異なるため、FastAPI の `CORSMiddleware` で以下を許可する。

- 許可オリジン: `http://localhost:5173`、`http://127.0.0.1:5173`（開発用。本番想定外）
- 許可メソッド: `GET, POST, DELETE, OPTIONS`
- 許可ヘッダー: `Content-Type, Accept-Language`
- 補足: Vite の `server.proxy` で `/api` をバックエンドへ転送する構成にすれば CORS 設定は不要になるが、本仕様では CORS 許可を標準とする。

### 1.3 リクエスト／レスポンス形式

| 項目 | 内容 |
|---|---|
| データ形式 | JSON（UTF-8） |
| リクエスト Content-Type | `application/json`（Body を持つ POST で必須） |
| レスポンス Content-Type | `application/json; charset=utf-8`（204 は Body なし） |
| 日時形式 | ISO 8601、UTC、秒精度、末尾 `Z`（例: `2026-07-07T01:23:45Z`） |
| 数値 | JSON の整数のみを整数として扱う（`10.0`、`"10"`、`true` は整数ではない） |
| 未定義のフィールド | Body に仕様外のフィールドがあっても無視する |

### 1.4 言語切り替え

| 項目 | 内容 |
|---|---|
| ヘッダー | `Accept-Language` |
| 指定可能な値 | `ja`（日本語）、`en`（英語）、`zh`（中国語） |
| 既定値 | `ja`（ヘッダー未指定、または未対応の言語・解釈不能な値の場合） |
| 解釈ルール | 先頭の言語タグのプライマリ部分で判定する（例: `en-US,en;q=0.9` → `en`、`zh-CN` → `zh`）。厳密な q 値のソートは行わない |
| 対象 | エラーレスポンスの `error.message`（`details` 内の文字列を含む）。成功レスポンスの JSON にはメッセージを含めない（画面文言はフロント側で管理） |
| 確認用 | レスポンスヘッダー `Content-Language` に実際に採用した言語（`ja` / `en` / `zh`）を返す |
| 備考 | 中国語は参考訳（未検証）。文言の正式定義は Step 3 の `doc/error_and_i18n_definition.md` で行う |

`error.code` は言語に依存しない固定値であり、フロントエンドはコードを基準に処理分岐できる。

### 1.5 共通エラーレスポンス形式

全ての異常系（400 / 404 / 409 / 500）で、以下の JSON 構造を返す。

```json
{
  "error": {
    "code": "E001",
    "message": "（Accept-Language に応じた言語のメッセージ）",
    "details": {}
  }
}
```

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| error | object | 必須 | エラー情報のルート |
| error.code | string | 必須 | エラーコード（`E` + 3桁数字）。言語非依存 |
| error.message | string | 必須 | 利用者に表示できるメッセージ。`Accept-Language` で言語が切り替わる |
| error.details | object | 必須 | エラーごとの付加情報。無い場合は `{}`。内容は各エラーコードの定義を参照 |

### 1.6 エラーコード一覧（仮）

> **注記**: 以下のエラーコードの採番・名称は **仮** である。Step 3 の `doc/error_and_i18n_definition.md` で正式に定義し、メッセージ文言（日本語・英語・中国語）と紐付ける。正式定義で変更があった場合は本書を追随して更新する。

| コード | HTTP | 内容（仮） | `details` の内容 |
|---|---|---|---|
| E001 | 400 | リクエスト形式が不正（JSON 構文エラー、Body が JSON オブジェクトでない、Content-Type 不正など） | `{}` |
| E002 | 400 | 品目名が未指定、または空（空白のみを含む） | `{"field": "name"}` |
| E003 | 400 | 品目名が長すぎる（101文字以上） | `{"field": "name", "max_length": 100}` |
| E004 | 400 | 初期在庫数が不正（整数でない、負の値、範囲外） | `{"field": "quantity"}` |
| E005 | 400 | 増減量が不正（未指定、0、整数でない、範囲外） | `{"field": "delta"}` |
| E006 | 400 | expected_quantity が未指定、または整数でない | `{"field": "expected_quantity"}` |
| E007 | 400 | パスパラメータ `id` が不正（正の整数でない） | `{"field": "id"}` |
| E008 | 404 | 指定した品目が存在しない | `{"id": <指定されたID>}` |
| E009 | 409 | 同一名称の品目が既に存在する | `{"field": "name"}` |
| E010 | 409 | 在庫数の不一致（サーバ値と expected_quantity が異なる） | `{"item": <最新の品目オブジェクト>}` |
| E099 | 500 | サーバ内部エラー | `{}` |

### 1.7 バリデーション・エラーの方針（422 を使わず 400 に統一）

- FastAPI / Pydantic は既定で入力検証エラーを **422 Unprocessable Entity**（`{"detail": [...]}` 形式）で返すが、本システムでは **採用しない**。
- 入力検証エラーは **全て 400 Bad Request** とし、1.5 の共通エラー形式で返す。PBI の受入条件（PBI-2 の 5〜7、PBI-4 の 5〜6）が 400 と定めているため。
- 実装方針（Step 4 向け）:
  - `RequestValidationError` の例外ハンドラを登録し、422 の代わりに 400 + 共通エラー形式へ変換する。
  - Pydantic のエラー内容（`loc` / `type`）から対応するエラーコード（E001〜E007）を決定する。
  - `HTTPException` および想定外の例外（`Exception`）にもハンドラを登録し、共通エラー形式（404 / 500）で返す。FastAPI 既定の `{"detail": ...}` 形式を外部に露出させない。
  - 存在しないパス（ルーティング不一致）や許可されないメソッドは FastAPI 既定動作（404 / 405）のままで構わないが、可能であれば共通形式で返す（本書の対象外）。
- 検証の優先順位: ① リクエスト形式（E001）→ ② パスパラメータ（E007）→ ③ Body の各項目（定義順: name → quantity、または delta → expected_quantity）→ ④ 業務チェック（存在確認 E008 → 重複 E009 / 不一致 E010）。複数項目が不正でも、最初に検出した 1 件のみ返す。

### 1.8 品目オブジェクト（Item）

品目を表す JSON オブジェクト。API-1（配列要素）、API-2（レスポンス）、API-4（レスポンス）、E010 の `details.item` で共通して使用する。

| 項目 | 型 | 必須 | 制約・説明 |
|---|---|---|---|
| id | integer | 必須 | 品目ID。サーバが自動採番（1以上、単調増加）。変更不可 |
| name | string | 必須 | 品目名。1〜100文字、前後空白除去後の値を保存・返却する。大文字小文字は入力のまま保持する |
| quantity | integer | 必須 | 現在の在庫数。**マイナス値を取りうる**（増減の結果としてのみ発生。赤文字表示はフロントの責務） |
| created_at | string | 必須 | 登録日時（ISO 8601 UTC）。変更不可 |
| updated_at | string | 必須 | 最終更新日時（ISO 8601 UTC）。登録時は `created_at` と同値。在庫増減のたびに更新 |

```json
{
  "id": 1,
  "name": "ボールペン（黒）",
  "quantity": 10,
  "created_at": "2026-07-07T01:23:45Z",
  "updated_at": "2026-07-07T01:23:45Z"
}
```

### 1.9 データ制約・採用ルール（PBI 未確定事項の確定内容）

| 項目 | 確定内容 |
|---|---|
| 品目名の文字数 | 前後空白除去後に 1〜100 文字（Unicode のコードポイント数で数える） |
| 空白の除去 | 先頭・末尾の空白（全角空白を含む Unicode 空白）を除去。名称内部の空白は保持 |
| 同一名称の判定 | 前後空白除去 + 大文字小文字を区別しない（`casefold`）で比較。全角/半角の違いは **区別する**（NFKC 正規化は行わない） |
| 同一名称時のステータス | 409 Conflict（E009） |
| 初期在庫数 | 省略可。省略時 0。0 以上の整数。マイナスの初期値は不可 |
| 増減量（delta） | 0 以外の整数。上限・下限の業務ルールは設けないが、SQLite の整数範囲（符号付き64bit）を超える値、および増減後の在庫数がその範囲を超える場合は 400（E005）とする |
| マイナス在庫 | 許容する（増減の結果、在庫数が 0 未満になってもエラーにしない） |
| 在庫0でない品目の削除 | 許可する |
| 一覧の並び順 | ID 昇順（登録順）。更新の前後で変わらない |
| 認証・認可 | 無し（演習の対象外） |
| ページング | 無し（一覧は常に全件返す） |

### 1.10 非機能要件

| 項目 | 内容 |
|---|---|
| レスポンス時間 | **全API（API-1〜API-4）で 0.2 秒（200ms）以内** |
| 測定条件 | ローカル環境（サーバとクライアントが同一マシン）、DB に品目が 100 件登録されている状態で、リクエスト送信からレスポンス受信完了までを測定。ネットワーク遅延は含まない |
| 対象 | 正常系・異常系（400 / 404 / 409）の両方 |
| 同時更新 | 複数の利用者が同時に操作しうるものとする。在庫増減は `UPDATE items SET quantity = quantity + :delta, updated_at = :now WHERE id = :id AND quantity = :expected` のように **条件付きの単一更新** で行い、判定と更新の間に他の更新が入らないようにする |
| 名称の一意性 | 正規化名称（前後空白除去 + `casefold` した値）に UNIQUE 制約を設け、同時登録の競合時も 409（E009）とする |

### 1.11 フロントエンドの利用方針（参考）

PBI の共通受入条件に基づく、API 利用側の動作。API 仕様の一部ではないが、設計意図として記す。

- 追加・削除・増減の完了後は、成功・失敗を問わず API-1 で一覧を再取得して画面を最新化する。
- 409（E010）では、トーストで `error.message` を表示した上で、`details.item` または API-1 の再取得結果で画面を更新する。
- 404（E008）では、トーストを表示した上で一覧を再取得する。
- 一覧取得の失敗（500・接続不可）では、トーストを表示し、直前の一覧表示を維持する。

## 2. API-1: 品目一覧の取得

| 項目 | 内容 |
|---|---|
| メソッド・URI | `GET /api/items` |
| 概要 | 登録済みの全品目を ID 昇順で返す。0 件の場合は空配列を返す（エラーにしない） |
| 対応PBI | PBI-1（受入条件 1〜5）、共通条件 1〜5 |

### リクエスト

**Headers**

| 項目 | 型 | 必須 | 制約・説明 |
|---|---|---|---|
| Accept-Language | string | 任意 | `ja` / `en` / `zh`。既定 `ja`（エラー時のメッセージ言語に影響） |

**Path パラメータ**: なし

**Query パラメータ**: なし（フィルタ・ソート・ページングは非対応。指定されても無視する）

**JSON Body**: なし

### レスポンス

**正常系: 200 OK**

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| items | array of Item | 必須 | 品目オブジェクトの配列（ID 昇順）。0 件なら `[]` |

```json
{
  "items": [
    {
      "id": 1,
      "name": "ボールペン（黒）",
      "quantity": 10,
      "created_at": "2026-07-07T01:23:45Z",
      "updated_at": "2026-07-07T01:23:45Z"
    },
    {
      "id": 2,
      "name": "A4コピー用紙",
      "quantity": -3,
      "created_at": "2026-07-07T01:30:00Z",
      "updated_at": "2026-07-07T02:10:12Z"
    }
  ]
}
```

0 件の場合:

```json
{ "items": [] }
```

> 一覧をトップレベルの配列ではなくオブジェクトで包むのは、将来の拡張（件数、ページング情報等の追加）で互換性を保つため。

**異常系: 500 Internal Server Error**（E099）

```json
{
  "error": {
    "code": "E099",
    "message": "サーバ内部でエラーが発生しました。しばらくしてからもう一度お試しください。",
    "details": {}
  }
}
```

> 400 / 404 / 409 は本APIでは発生しない。

## 3. API-2: 品目の追加

| 項目 | 内容 |
|---|---|
| メソッド・URI | `POST /api/items` |
| 概要 | 新しい品目を登録する。品目名は前後空白を除去して保存し、既存品目と同一名称（前後空白除去 + 大文字小文字無視）の場合は 409 を返す |
| 対応PBI | PBI-2（受入条件 1〜7）、共通条件 1〜5 |

### リクエスト

**Headers**

| 項目 | 型 | 必須 | 制約・説明 |
|---|---|---|---|
| Content-Type | string | 必須 | `application/json` |
| Accept-Language | string | 任意 | `ja` / `en` / `zh`。既定 `ja` |

**Path パラメータ**: なし

**Query パラメータ**: なし

**JSON Body**

| 項目 | 型 | 必須 | 制約 |
|---|---|---|---|
| name | string | 必須 | 前後空白を除去した後 1〜100 文字。未指定・`null`・文字列以外・空白のみは E002。101 文字以上は E003。既存品目との重複（前後空白除去 + 大文字小文字無視）は E009 |
| quantity | integer | 任意 | 初期在庫数。省略時 `0`。0 以上の整数。小数・文字列・真偽値・`null`・負の値・範囲外は E004 |

リクエスト例（初期在庫数あり）:

```json
{ "name": "ボールペン（黒）", "quantity": 10 }
```

リクエスト例（初期在庫数を省略 → 0 で登録）:

```json
{ "name": "  付箋  " }
```

### レスポンス

**正常系: 201 Created**

- Body: 登録された Item オブジェクト（`name` は前後空白除去後の値）
- ヘッダー: `Location: /api/items/{id}`

```json
{
  "id": 3,
  "name": "付箋",
  "quantity": 0,
  "created_at": "2026-07-07T03:00:00Z",
  "updated_at": "2026-07-07T03:00:00Z"
}
```

**異常系: 400 Bad Request**

品目名が空（E002）:

```json
{
  "error": {
    "code": "E002",
    "message": "品目名は必須です。",
    "details": { "field": "name" }
  }
}
```

品目名が長すぎる（E003）:

```json
{
  "error": {
    "code": "E003",
    "message": "品目名は100文字以内で入力してください。",
    "details": { "field": "name", "max_length": 100 }
  }
}
```

初期在庫数が不正（E004）:

```json
{
  "error": {
    "code": "E004",
    "message": "初期在庫数は0以上の整数で指定してください。",
    "details": { "field": "quantity" }
  }
}
```

リクエスト形式が不正（E001。JSON 構文エラー等）:

```json
{
  "error": {
    "code": "E001",
    "message": "リクエストの形式が正しくありません。",
    "details": {}
  }
}
```

**異常系: 404 Not Found**: 本APIでは発生しない。

**異常系: 409 Conflict**（E009: 同一名称）

```json
{
  "error": {
    "code": "E009",
    "message": "同じ名称の品目が既に登録されています。",
    "details": { "field": "name" }
  }
}
```

> 既存品目は変更されない。

**異常系: 500 Internal Server Error**（E099）

```json
{
  "error": {
    "code": "E099",
    "message": "サーバ内部でエラーが発生しました。しばらくしてからもう一度お試しください。",
    "details": {}
  }
}
```

## 4. API-3: 品目の削除

| 項目 | 内容 |
|---|---|
| メソッド・URI | `DELETE /api/items/{id}` |
| 概要 | 指定した品目を物理削除する。在庫数に関わらず（マイナス在庫を含む）削除できる。他の品目には影響しない |
| 対応PBI | PBI-3（受入条件 1〜4）、共通条件 1〜5 |

> 削除前の確認ダイアログ（PBI-3 受入条件 2）はフロントエンドの責務であり、本APIは確認なしで即時削除する。

### リクエスト

**Headers**

| 項目 | 型 | 必須 | 制約・説明 |
|---|---|---|---|
| Accept-Language | string | 任意 | `ja` / `en` / `zh`。既定 `ja` |

**Path パラメータ**

| 項目 | 型 | 必須 | 制約 |
|---|---|---|---|
| id | integer | 必須 | 削除対象の品目ID。1 以上の整数。整数でない・0 以下は E007。存在しなければ E008 |

**Query パラメータ**: なし

**JSON Body**: なし

### レスポンス

**正常系: 204 No Content**

- Body なし。

> 削除済みの ID に対する再度の DELETE は冪等扱いにせず 404（E008）を返す（PBI-3 受入条件 4）。

**異常系: 400 Bad Request**（E007: id が不正。例 `DELETE /api/items/abc`）

```json
{
  "error": {
    "code": "E007",
    "message": "品目IDの指定が正しくありません。",
    "details": { "field": "id" }
  }
}
```

**異常系: 404 Not Found**（E008）

```json
{
  "error": {
    "code": "E008",
    "message": "指定された品目が存在しません。",
    "details": { "id": 99 }
  }
}
```

**異常系: 409 Conflict**: 本APIでは発生しない。

**異常系: 500 Internal Server Error**（E099）

```json
{
  "error": {
    "code": "E099",
    "message": "サーバ内部でエラーが発生しました。しばらくしてからもう一度お試しください。",
    "details": {}
  }
}
```

## 5. API-4: 在庫の増減

| 項目 | 内容 |
|---|---|
| メソッド・URI | `POST /api/items/{id}/adjust` |
| 概要 | 指定した品目の在庫数に `delta`（正: 入庫、負: 出庫）を加算する。クライアントが認識している在庫数 `expected_quantity` とサーバ上の現在値が一致する場合のみ更新し、不一致なら **更新せず 409 と最新の品目情報を返す**（楽観ロック）。マイナス在庫は許容する |
| 対応PBI | PBI-4（受入条件 1〜7）、共通条件 1〜5 |

> **メソッドの選定理由**: 増減は「現在値に対する相対操作」であり、同じリクエストを再送すると結果が変わる（冪等でない）。PUT / PATCH（リソースの状態を指定値で置換・部分更新する意味合い）ではなく、操作を表す `POST .../adjust` とした。

### リクエスト

**Headers**

| 項目 | 型 | 必須 | 制約・説明 |
|---|---|---|---|
| Content-Type | string | 必須 | `application/json` |
| Accept-Language | string | 任意 | `ja` / `en` / `zh`。既定 `ja` |

**Path パラメータ**

| 項目 | 型 | 必須 | 制約 |
|---|---|---|---|
| id | integer | 必須 | 対象の品目ID。1 以上の整数。整数でない・0 以下は E007。存在しなければ E008 |

**Query パラメータ**: なし

**JSON Body**

| 項目 | 型 | 必須 | 制約 |
|---|---|---|---|
| delta | integer | 必須 | 増減量。**0 以外の整数**（正: 増加、負: 減少）。未指定・`null`・0・小数・文字列・真偽値・範囲外（増減後の在庫数が符号付き64bit範囲外となる場合を含む）は E005 |
| expected_quantity | integer | 必須 | クライアント（画面）が保持している現在の在庫数。整数（負の値も可）。未指定・`null`・整数でない場合は E006 |

リクエスト例（在庫 10 の品目に +5）:

```json
{ "delta": 5, "expected_quantity": 10 }
```

リクエスト例（在庫 2 の品目に -5 → マイナス在庫 -3 になる）:

```json
{ "delta": -5, "expected_quantity": 2 }
```

### 処理ルール

1. `id` の形式検査 → Body の検査（`delta` → `expected_quantity`）。
2. 品目の存在確認（なければ 404）。
3. `quantity = expected_quantity` の場合のみ `quantity = quantity + delta` に更新し、`updated_at` を現在時刻にする（1 文の条件付き UPDATE で原子的に実施）。
4. 更新行が 0 件で、品目が存在する場合は不一致として 409（E010）を返し、**その時点の最新の品目オブジェクトを `details.item` に含める**。更新行が 0 件で品目も存在しない場合（判定の間に削除された場合）は 404（E008）。

### レスポンス

**正常系: 200 OK**

- Body: 更新後の Item オブジェクト（画面はこの値、または一覧の再取得結果で表示を更新する）

在庫 10 に +5（expected_quantity=10）の場合:

```json
{
  "id": 1,
  "name": "ボールペン（黒）",
  "quantity": 15,
  "created_at": "2026-07-07T01:23:45Z",
  "updated_at": "2026-07-07T04:00:00Z"
}
```

在庫 2 に -5（expected_quantity=2）の場合（エラーではなくマイナス在庫として 200）:

```json
{
  "id": 2,
  "name": "A4コピー用紙",
  "quantity": -3,
  "created_at": "2026-07-07T01:30:00Z",
  "updated_at": "2026-07-07T04:05:00Z"
}
```

**異常系: 400 Bad Request**

増減量が不正（E005。未指定・0・整数でない）:

```json
{
  "error": {
    "code": "E005",
    "message": "増減量は0以外の整数で指定してください。",
    "details": { "field": "delta" }
  }
}
```

expected_quantity が不正（E006）:

```json
{
  "error": {
    "code": "E006",
    "message": "現在の在庫数（expected_quantity）は整数で指定してください。",
    "details": { "field": "expected_quantity" }
  }
}
```

id が不正（E007）:

```json
{
  "error": {
    "code": "E007",
    "message": "品目IDの指定が正しくありません。",
    "details": { "field": "id" }
  }
}
```

リクエスト形式が不正（E001）は API-2 と同様。

**異常系: 404 Not Found**（E008）

```json
{
  "error": {
    "code": "E008",
    "message": "指定された品目が存在しません。",
    "details": { "id": 99 }
  }
}
```

**異常系: 409 Conflict**（E010: 在庫数の不一致。在庫は更新されない）

例: 画面は在庫 10 と認識しているが、他の利用者が先に更新して現在は 12 の場合。

```json
{
  "error": {
    "code": "E010",
    "message": "在庫数が他の操作により更新されています。最新の在庫数を表示しました。",
    "details": {
      "item": {
        "id": 1,
        "name": "ボールペン（黒）",
        "quantity": 12,
        "created_at": "2026-07-07T01:23:45Z",
        "updated_at": "2026-07-07T03:55:00Z"
      }
    }
  }
}
```

> 画面はトーストで `error.message` を表示し、`details.item` を反映するか、一覧を再取得して最新の状態を表示する（PBI-4 受入条件 4）。

**異常系: 500 Internal Server Error**（E099）

```json
{
  "error": {
    "code": "E099",
    "message": "サーバ内部でエラーが発生しました。しばらくしてからもう一度お試しください。",
    "details": {}
  }
}
```

## 7. トレーサビリティ（pbi.md の受入条件とAPIの対応）

「AC」は受入条件の番号。【受講者】【AI補完】は pbi.md の区分。画面側（フロントエンド）の責務となる条件は、対応APIと API 側で担保する内容を併記する。

### PBI-1: 品目と在庫数の一覧を表示する

| AC | 区分 | 条件の要約 | エンドポイント | ステータス | API 側で担保する内容 |
|---|---|---|---|---|---|
| 1 | 受講者 | 画面更新時に DB と一致 | API-1 | 200 | DB の全品目の name / quantity をそのまま返す |
| 2 | 受講者 | マイナス在庫を赤文字表示 | API-1 | 200 | `quantity` を負値のまま返す（赤文字はフロント） |
| 3 | AI補完 | 0 件の空状態 | API-1 | 200 | `{"items": []}` を返す（エラーにしない）。空状態メッセージはフロント |
| 4 | AI補完 | ID 昇順 | API-1 | 200 | `ORDER BY id ASC` で返す |
| 5 | AI補完 | 一覧取得の失敗時にトースト・一覧維持 | API-1 | 500 | 共通エラー形式（E099）。トースト表示・直前一覧の維持はフロント |

### PBI-2: 品目を追加する

| AC | 区分 | 条件の要約 | エンドポイント | ステータス | API 側で担保する内容 |
|---|---|---|---|---|---|
| 1 | AI補完 | 有効な名称・初期在庫で登録 | API-2 | 201 | Item を返し、指定した quantity で保存 |
| 2 | AI補完 | 初期在庫数の省略時は 0 | API-2 | 201 | `quantity` 省略時 0 で登録 |
| 3 | 受講者 | 同一名称は登録エラー | API-2 | 409 (E009) | 登録せず、既存品目は変更しない |
| 4 | AI補完 | 前後空白除去＋大文字小文字無視で同一判定 | API-2 | 409 (E009) | 正規化名称で一意判定 |
| 5 | AI補完 | 品目名が空・空白のみ | API-2 | 400 (E002) | 登録せず、必須エラー |
| 6 | AI補完 | 品目名が 100 文字超 | API-2 | 400 (E003) | 登録せず、エラー |
| 7 | AI補完 | 初期在庫数が不正（小数・文字列・負） | API-2 | 400 (E004) | 登録せず、エラー |

### PBI-3: 品目を削除する

| AC | 区分 | 条件の要約 | エンドポイント | ステータス | API 側で担保する内容 |
|---|---|---|---|---|---|
| 1 | AI補完 | 品目の削除（他品目に影響なし） | API-3 | 204 | 指定IDのみ物理削除 |
| 2 | AI補完 | 削除前の確認ダイアログ | （API なし） | - | フロントの責務。API は確認なしで削除 |
| 3 | AI補完 | 在庫が 0 でない品目も削除可 | API-3 | 204 | 在庫数に関わらず削除（マイナス在庫を含む） |
| 4 | AI補完 | 存在しない品目の削除 | API-3 | 404 (E008) | 共通エラー形式で返す。トースト・一覧再取得はフロント |

### PBI-4: 在庫数を増減する

| AC | 区分 | 条件の要約 | エンドポイント | ステータス | API 側で担保する内容 |
|---|---|---|---|---|---|
| 1 | AI補完 | +5 で 10 → 15 | API-4 | 200 | 更新後の Item を返す |
| 2 | AI補完 | -3 で 10 → 7 | API-4 | 200 | 更新後の Item を返す |
| 3 | 受講者 | マイナス在庫を許容（2 → -3） | API-4 | 200 | エラーにせず負値で保存・返却。赤文字はフロント |
| 4 | 受講者 | 画面とサーバの在庫数の不一致 | API-4 | 409 (E010) | 更新せず、`details.item` に最新の Item を返す。トースト・再取得はフロント |
| 5 | AI補完 | 増減量が 0・非整数・未指定 | API-4 | 400 (E005) | 更新しない |
| 6 | AI補完 | expected_quantity が未指定・非整数 | API-4 | 400 (E006) | 更新しない |
| 7 | AI補完 | 存在しない品目の増減 | API-4 | 404 (E008) | 共通エラー形式で返す。トースト・一覧再取得はフロント |

### 共通の受入条件

| AC | 区分 | 条件の要約 | エンドポイント | ステータス | API 側で担保する内容 |
|---|---|---|---|---|---|
| 1 | 受講者 | 全操作 0.2 秒以内 | API-1〜4 | 全て | 1.10 の非機能要件 |
| 2 | AI補完 | 測定条件（ローカル・100 件） | API-1〜4 | 全て | 1.10 の測定条件 |
