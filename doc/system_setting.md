# 対象とするシステムの設定（§1）

- **システム名**: 在庫管理システム
- **概要**: 総務部が扱う日用品（文具・消耗品など）の品目と在庫数を管理するシステム
- **対象のストーリー**: 総務担当者が、品目の一覧確認・追加・削除および在庫の増減を行い、日用品の在庫を常に正しく把握できる
- **対象となる主要機能**:
  - 一覧表示
  - 品目の追加
  - 品目の削除
  - 在庫の増減
- **受入条件の下書き（受講者記入）**:
  - 同一名称の品目を登録時はエラーとする。
  - 在庫の増減は、サーバ側とフロント側の在庫数が一致していない場合は、画面にトーストなどでエラーメッセージを表示した上で最新の状態を取得して画面に反映させる。
  - 全ての操作のレスポンスが0.2秒以内であること。
  - 全ての操作において、在庫情報の再取得を行い、画面を最新化すること。
  - 画面を更新した時、DBの品目・在庫数が画面に正しく表示されること。
  - マイナス在庫は許容すること（ただし赤文字にして、明確に例外運用していることを示すこと）。
- **使用する言語・フレームワーク**:
  - バックエンド: Python (FastAPI) + SQLite
  - フロントエンド: React + TypeScript（Vite）

## 設計上の前提（受入条件から導いたもの）
- 在庫の不一致検知: フロントは在庫増減リクエスト時に「画面上の現在在庫数（expected_quantity）」を送る。サーバ側の値と異なれば **409 Conflict** と最新の品目情報を返す。
